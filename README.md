# 1688 订单详情页批量截图工具

这是一个 Windows 可用的 Python + Playwright 命令行工具，用于批量打开你有权限访问的 1688 订单详情页，并截取页面中间的订单主体内容区域为 PNG 图片。

工具不会保存 1688 账号密码，不会自动破解验证码、滑块、安全验证或平台风控。遇到登录或验证页面时，程序会暂停，等待你在浏览器里手动完成后再继续。

## 安装依赖

进入项目目录：

```powershell
cd D:\1688_order_screenshot
```

安装 Python 依赖：

```powershell
pip install -r requirements.txt
```

安装 Playwright 浏览器：

```powershell
python -m playwright install chromium
```

如果电脑已安装 Chrome，程序会优先尝试控制本机 Chrome；找不到 Chrome 时会自动尝试本机 Edge；两者都不可用时才会尝试 Playwright Chromium。

可视化界面里的“浏览器路径”可以留空。只有绿色版、便携版、公司定制版浏览器等自动识别不到的情况，才需要手动选择 `chrome.exe` 或 `msedge.exe`。

## 首次登录

首次运行时，如果没有发现登录状态文件：

```text
auth/1688_login_state.json
```

程序会打开可见浏览器并进入 `https://login.1688.com/member/signin.htm`。请在浏览器里手动登录 1688，完成登录或安全验证后，回到可视化界面点击“我已处理完成，继续”；如果使用命令行运行，则回到命令行按回车。程序会用 Playwright 的 `storage_state` 保存登录状态，后续运行会自动复用。

如果登录入口出现 404，可在可视化界面的“登录入口”里改成 `https://login.1688.com/` 后再试。

如果登录页、扫码区或安全验证区域显示不完整，请在可视化界面把“登录窗宽”和“登录窗高”调大，例如 `1366 x 900` 或 `1440 x 1000`，然后重新开始。登录窗口尺寸只影响人工登录/验证阶段，不影响最终截图区域。

如果订单详情页本身出现 404，可能是 1688 调整了订单详情地址。可在可视化界面的“订单链接模板”里改成新的地址模板，模板里用 `{order_id}` 表示订单号。例如：

```text
https://air.1688.com/app/ctf-page/trade-order-detail/index.html?orderId={order_id}
```

如果登录状态文件损坏或失效，程序会删除旧文件并重新进入手动登录流程。

默认情况下，登录状态从最近一次人工登录或人工验证完成开始计算，24 小时后自动失效并要求重新登录。可视化界面里可以修改“登录状态有效期（小时）”；填写 `0` 表示不按时间强制失效。计时信息保存在：

```text
auth/1688_login_state.meta.json
```

## 输入文件

支持 txt、xlsx、xls。

txt 示例，每行一个订单号：

```text
5118000000000000001
5118000000000000002
5118000000000000003
```

Excel 示例，表头可使用以下任一字段：

```text
订单号
订单编号
order_id
orderId
订单ID
```

订单号会按字符串读取，自动去除空行和前后空格。建议 Excel 中把订单号列设置为文本格式，避免长数字被 Excel 自动转成科学计数法或损失精度。

## 运行示例

### 可视化界面

推荐使用可视化界面：

```powershell
python gui.py
```

也可以双击项目里的 `start_gui.bat`。程序会自动打开一个本地控制台页面，地址类似 `http://127.0.0.1:8765`。界面里选择订单文件和截图保存目录后，点击“开始截图”。如果中途需要登录、验证码、滑块或安全验证，页面会显示“我已处理完成，继续”按钮；你在浏览器里手动处理完成后，再回到控制台页面点击继续。

界面的“任务来源”提供两个互不影响的模式：

- `导入订单号文件（原功能）`：继续按 txt / Excel 中的订单号截图，并可选择不分类、按收货人分类或按手机号分类。
- `按时间抓取已支付订单`：从 1688 订单列表自动抓单，按时间和付款状态筛选后批量截图。

按时间抓单支持今天、昨天、最近三天、最近七天、本月和自定义开始/结束日期。程序只处理明确显示为已支付、已付款、待发货、已发货、待收货、交易成功等已付款状态的订单；未支付、已取消、已关闭和状态或日期无法确认的订单不会进入详情页。

程序会在1688订单列表的“下单时间”筛选框中选择真实日期，填写实际开始、结束日期并点击“搜索”。抓单结束后，控制台会分别显示扫描候选数、时间范围内订单数、已支付数、未支付数、取消/关闭数、其它状态数、超出范围数和日期不明数。“时间范围内订单”才是所选日期内的总订单数量，扫描候选数只是程序翻页检查过的数量。只有点击“确认并开始截图”后才会逐个进入订单详情。两个任务模式都支持“不分类、按收货人、按手机号”三种保存方式，默认不分类并把全部截图放入一个文件夹；未识别到分类信息时会保存到“未识别收货人”或“未识别手机号”目录。日期模式完成后还会生成带时间戳的 Excel、JSON 结果文件。

如果需要汇总订单金额，勾选“读取每笔订单实付款，并在每个分类文件夹导出 Excel 汇总表”。该选项同时支持订单号文件模式和日期模式。程序会在每个订单详情页读取“实付款”，并按照最终截图目录分别生成：

```text
订单实付款汇总.xlsx
```

选择“不分类”时，输出目录只有一张总表；按收货人或手机号分类时，每个分类文件夹都有自己的表格，表内只包含该文件夹的订单。不勾选时不会读取金额，也不会生成实付款表格。

### 命令行

```powershell
python main.py --input D:\orders.txt --output D:\1688订单截图
```

可选参数：

```powershell
python main.py `
  --input D:\orders.xlsx `
  --output D:\1688订单截图 `
  --viewport-width 1440 `
  --viewport-height 1800 `
  --clip-x 250 `
  --clip-y 80 `
  --clip-width 950 `
  --clip-height 1500 `
  --retries 3 `
  --export-payment-table `
  --browser-path "C:\Program Files\Google\Chrome\Application\chrome.exe"
```

`--browser-path` 是可选参数。留空时会自动按“Chrome -> Edge -> Playwright Chromium”的顺序尝试。

`--export-payment-table` 是可选参数。加上后会读取每笔订单的实付款，并在输出目录导出 `订单实付款汇总.xlsx`。

默认不开启无头模式。如果要无头运行：

```powershell
python main.py --input D:\orders.txt --output D:\1688订单截图 --headless
```

注意：无头模式无法手动处理登录、验证码、滑块或安全验证。需要人工处理时，请去掉 `--headless` 重新运行。

## 截图范围

程序优先进入 `app-root.shadowRoot`，定位以下区域并计算联合截图范围：

```text
main.main-container
q-theme
.stage-container
detail-tabs
.detail-container
```

截图会尽量包含：

- 顶部订单流程状态
- 当前订单状态提示
- 订单信息、物流信息、交易方式 tab
- 买家、卖家、商品和金额汇总信息
- 底部操作按钮区域

如果精准定位失败，会依次尝试：

1. 主容器截图
2. 文字锚点截图
3. 固定 clip 截图

固定 clip 默认值：

```text
x=250
y=80
width=950
height=1500
```

可以通过 `--clip-x`、`--clip-y`、`--clip-width`、`--clip-height` 调整。

## 输出和日志

截图文件以订单号命名：

```text
output/
  5118000000000000001.png
  5118000000000000002.png
```

订单号文件模式和日期模式都可以增加收货人或手机号分类目录；截图文件名仍然只是订单号，每个分类文件夹可单独生成实付款表格：

```text
output/
  张三/
    5118000000000000001.png
    订单实付款汇总.xlsx
  13800138000/
    5118000000000000002.png
    订单实付款汇总.xlsx
  已支付订单截图结果_20260726_203000.xlsx
  已支付订单截图结果_20260726_203000.json
```

成功订单写入：

```text
logs/success.log
```

失败订单写入：

```text
logs/failed.log
```

失败日志包含失败时间、订单号和失败原因。单个订单失败不会终止整个任务，每个订单默认最多重试 3 次。

## 登录或验证处理

程序会检测登录页、验证码页、安全验证页、滑块验证页、访问受限、风险提示等页面。检测到后会暂停并提示：

```text
检测到需要登录或安全验证。请在浏览器中手动完成，完成后回到命令行按回车继续。
```

你手动处理完成后按回车，程序会重新保存最新登录状态，并继续当前订单任务。

## 常见问题

1. 截图区域不准确  
   先调整 `--viewport-width`、`--viewport-height`，再调整固定 clip 参数。程序只有在精准定位和备用定位都失败时才会使用固定 clip。

2. Excel 订单号变成科学计数法  
   请把 Excel 订单号列设置为文本格式后重新保存。已经被 Excel 截断精度的长数字无法由程序恢复。

3. 提示无权限或页面加载异常  
   请确认当前 1688 账号确实有权限查看该订单详情页。无权限订单会写入失败日志并跳过。

4. 经常触发验证  
   不要高频运行。工具默认每个订单之间等待 1 到 3 秒，也可以用 `--delay-min` 和 `--delay-max` 增加等待时间。

5. 登录状态一直失效  
   删除 `auth/1688_login_state.json` 后重新运行，按提示重新手动登录。

## 打包 EXE

项目已提供打包脚本：

```powershell
python build_exe.py
```

或双击：

```text
build_exe.bat
```

打包产物在：

```text
dist/1688订单截图工具/1688订单截图工具.exe
```

分发给其他电脑时，建议整个 `dist/1688订单截图工具` 文件夹一起复制，或直接发送 `dist/1688订单截图工具.zip`。这个版本优先使用对方电脑已安装的 Chrome，找不到 Chrome 时会自动尝试 Edge。

打包版不依赖 Tkinter。打开 exe 后会自动启动本地网页控制台；如果浏览器没有自动弹出，可手动打开程序日志里显示的 `http://127.0.0.1:端口/` 地址。
